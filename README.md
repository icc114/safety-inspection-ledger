# 安全检查台账 Android

真正独立的 Android 原生离线优先应用。包名 `cn.safetyledger.app`，当前版本 `1.2.5`（versionCode 8），最低 Android 8.0（API 26）。工程由新的 Java 17 / Android SDK 源码编译，不包含 WebView、旧 APK、DEX、旧 Manifest、旧数据库或旧软件代码。

## 当前已完成

- 首页台账中心：标题旁使用小号矢量设置图标，各页返回图标同步缩小；提供检查填报、紧凑七列月历和记录列表；有检查的日期显示黄色五角星，不再使用蓝底，国务院正式法定假日为红字。
- 筛选与分页：当日、月、季度、年度、全部，检查类型、整改状态，10/20/50/100/200 条每页；多选导出下“全选”会切换为“取消全选”，导出可选择逐条独立 PDF 或合并 PDF，合并时可按检查日期正序/倒序排列。
- 填报页通过表单内下拉框直接切换基础设施/检查模板，避免弹窗无法选择；首次建库提供可编辑的“车棚安全检查”8 项初始模板，不在 UI 代码中写死。
- 模板管理：新建、改名、改类别、启用/停用、删除；项目新增、编辑、删除、上移/下移，删除后序号自动压紧。检查保存模板快照，历史不随模板修改。
- 检查填报采用紧凑表格业务流程：前置内容只保留检查日期和检查地点；每项只选择“是/否”，“否”时必须填写现场情况、发现问题及整改要求。不再显示不适用、检查结论、独立整改意见、责任人和期限字段。
- 照片：Android 13+ 使用系统照片网格多选，旧系统回退到手机相册，不再主动打开通用文档/“安全访问”界面；导入超大原图和列表缩略图均按目标尺寸采样解码，避免照片上传后因内存占用过高退出填报页；缩略图可进入全屏预览并支持双击、双指缩放。业务照片与原始照片保存于 APP 私有媒体体系；优先读取 EXIF 原始拍摄时间、方向与 GPS，GPS 显示为“北纬/南纬、东经/西经”中文格式，缺失的元数据不会用当前填报信息伪造水印。
- 草稿：离开填报页、调用相机/相册或进入签名页时自动保存当前日期、地点、勾选和问题内容；首页记录列表中的“草稿”可点击后继续编辑，不再误入只读详情页。
- 保存后补录：记录详情/整改页保留“补拍检查照片、从相册补传”和三方“补签/重签”入口；即使首次只勾选检查结果就保存，也能随后补齐检查照片和任一方签名，不会被限制为只能补录整改资料。
- 照片大图预览：填报页和记录详情页的整条照片区域均可点击，打开沉浸式大图；支持双击放大/还原、双指缩放和单指拖动。照片文件缺失时明确提示需要先从云端下载，不再出现点击无反应。
- 整改闭环：存在“否”项时进入待整改；详情页补录整改情况和整改照片，并通过“整改确认：已整改完成”明确确认。确认前强制要求整改说明和至少一张整改照片。
- 三方电子签名：检查人员 1、检查人员 2、被检查人；横屏沉浸式隐藏状态栏和导航栏、5dp 圆角平滑笔迹，角色提示及清空/确认压缩到 34dp 单行工具栏，左右增加 26dp 曲面屏安全边距；签名使用不可变版本文件保存，避免旧设备快照覆盖新签名，可重新查看并进入 PDF。
- 正式 A4 PDF：单条、多选、按月/季度/年度/全部合并导出；首页按参考表格固定为“日期与地点—类别—序号—检查内容及标准—是/否—现场情况/问题—整改记录—三方签名”，模板新增项目后动态调整行高和字号并保持检查表在一页，照片始终从该记录第二页开始；同一日期统一计算总页数，换日期重新从第 1 页开始。导出前校验本地媒体，缺失会明确停止。
- APP 数据备份：基础设置提供明确的“导出数据”“导入数据”“设备迁移”三个入口，通过 Android 系统文件选择器生成/选择可复制到另一手机或电脑的 `.safetydata` 文件；耗时的打包、校验和恢复均在后台线程执行并显示进度。新版便携备份无需用户另设密码，包含数据库、设置和全部业务媒体，并用独立魔数、格式/schema 版本、SHA-256 与 AES-256-GCM 校验文件完整性。1.2.3 及更早的密码备份仍可输入旧密码导入，损坏文件和 PDF 会被拒绝。
- 跨端数据包：`docs/safetydata-format-v2.md` 公开容器、加密、清单和目录结构；`tools/SafetyDataTool.java` 可直接在 Windows/macOS/Linux 的 JDK 17 上查看、校验、解包和重新打包。重新打包的数据可回到 Android“导入数据”，实现同一数据包在手机和 PC 间往返；Windows 图形客户端仍是后续交付。
- 恢复：合并恢复不覆盖相同 UUID，差异记录建立冲突副本；完整恢复保留恢复前数据库副本；跨设备恢复后重建照片与签名本地路径。
- 删除：普通删除进回收站，可恢复；永久删除要求 PBKDF2 密码并二次确认，删除本地媒体及数据库关联并写 tombstone。
- SQLite schema v2：v1 数据库通过显式 migration 新增 `sync_devices`，覆盖升级保留原记录；全部业务主键 UUID，记录/媒体/签名含版本与更新时间，保留 provider-neutral 云配置、同步队列、tombstone、冲突副本和归档索引。
- WebDAV/飞牛 NAS 真实同步：每台设备上传独立的 AES-256-GCM 加密 `.safetydata` 快照；同步时下载其他设备快照，按 UUID 与更新时间合并模板、记录、问题、整改、照片、签名、设备角色和 tombstone，再上传本机聚合快照。手动“立即同步”可用，Android JobScheduler 联网后约每 15 分钟执行后台同步，失败保留本地数据并发送通知。
- 严格连接测试：WebDAV/兼容 Worker 必须完成 `PROPFIND → MKCOL → PUT → GET → DELETE` 五步读写校验才显示成功；仅返回 HTTP 204 只表示地址可达，不再误报为同步可用。
- Cloudflare：仓库 `cloudflare-worker/` 提供可部署到私有 R2 的兼容 Worker；1.2.5 支持仅用“同步空间名称 + 同步密码”自动配对，原密码不会上传，Worker 只接收空间限定的 SHA-256 配对凭据。高级 Token/Basic 认证继续兼容。普通网页、R2 公共链接、仅返回 204 或使用未知私有设备授权协议的旧 Worker 会被明确拒绝。
- 云账号与密码：普通页面只显示“同步空间名称 + 同步密码”；同步密码用于跨设备配对、端到端加密和回收站永久删除验证。WebDAV 用户名/登录密码及 Cloudflare 设备 Token 收进高级服务器认证，它们只负责服务器授权，并不等于同步空间名称或同步密码。所有密码和 Token 输入均掩码显示，保存后立即清空，以 Android Keystore 密文保存。
- 多设备角色：界面统一使用“管理员 / 工作人员”。首台创建空同步空间的设备自动成为管理员，后加入设备自动成为工作人员；本机不能自行提权，管理员可查看已配对设备并调整角色，变更随下一次同步传播。管理员设备会拉取其他手机的完整记录、照片和签名。
- Cloudflare 兼容性：项目内 `cloudflare-worker/` 是当前 Android 客户端可直接使用的 WebDAV 兼容 R2 网关。旧 Worker 返回“需要设备授权”时必须重新部署本版 Worker，或在高级服务器认证中填写旧服务自己生成的设备 Token；客户端不会绕过服务端授权。
- 2026 年节假日：只缓存国务院办公厅正式公布的 2026 年放假调休安排及来源；未正式公布/未缓存年份不预测。
- GitHub Actions：Java 17、Android SDK、单元测试、Lint、`assembleDebug`、中文 APK artifact。

## 尚未完成（不冒充实现）

- Google Drive、OneDrive 的官方 OAuth provider，自定义非 WebDAV HTTP 协议，以及云 A 到云 B 的迁移执行器。当前 Cloudflare 必须部署仓库内兼容 Worker，WebDAV/飞牛 NAS 可直接使用。
- Android JobScheduler 的后台执行时间受各品牌手机省电策略影响，可能晚于 15 分钟；需要立刻收发时使用“立即同步”。当前同步为加密设备快照模型，尚未实现服务端签名的强权限体系；管理员角色由已配对客户端共同同步，不等同于企业级身份认证。
- 云端缺失媒体/归档 PDF 的自动回下载。目前导出会检测本地缺失并明确停止，不会静默输出不完整 PDF。
- “完成且已云端验证超过 180 天”自动生成归档 PDF、释放手机空间和手动“释放本机空间”界面。schema 已含 `archive_index`，在实际 provider 可验证远端文件前保持关闭。
- 从国务院网站自动抓取并校验新的节假日公告。当前 v1 仅内置 2026 年正式公告缓存，其他年份不会预测。
- Windows 原生客户端及类似微信的电脑端后台接收目录。本仓库当前只交付 Android；UUID、版本、设备角色、`.safetydata` 和同步 envelope 已按 Windows 兼容方向设计，`.safetydata` 可先手动复制到电脑保存。
- 真机 Camera/定位/系统文件选择器的设备矩阵测试及 UI 自动化测试；当前已通过 Java 单元测试、Android Lint 和本机 Gradle 构建。
- Android 系统照片选择器可能因系统隐私策略移除相册照片的 GPS EXIF；这种情况下保留原始照片和水印接口，但不显示虚假位置。APP 直接调用相机拍摄时可用本机定位作为 EXIF 缺失时的拍摄位置后备。

## 数据升级

数据库从 v1 开始，`LedgerDatabase.onUpgrade` 是唯一 migration 入口，未来升级必须逐版执行并写入 `schema_migrations`，不得使用破坏性重建。覆盖安装且签名相同会保留 APP 私有数据库和媒体。

## 本地构建

需要 JDK 17 与 Android SDK 35：

```shell
./gradlew testDebugUnitTest lintDebug assembleDebug
```

输出：`app/build/outputs/apk/debug/app-debug.apk`。CI artifact 名称为 `安全检查台账-1.2.5.apk`。
